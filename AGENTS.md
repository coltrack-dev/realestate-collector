# Project rules

- Do not git commit or push without explicit approval.
- Do not modify files outside this project.
- Never use existing or production databases; use the Compose database or an isolated test database.
- Do not bypass robots, terms, CAPTCHA, authentication, rate limits, or anti-bot controls.
- Preserve source HTML/JSON fixtures for reproducibility.
- Document architectural decisions and do not claim live functionality without verification.

## Качество кода

- Использовать понятные, полные имена переменных, функций и типов.
- Не использовать неинформативные сокращения.
- Соблюдать идиоматический стиль Go и Dart.
- Разделять бизнес-логику, инфраструктуру и HTTP-обработчики.
- Не дублировать бизнес-логику между клиентскими приложениями.
- Корректно обрабатывать ошибки.
- Не хранить секреты в исходном коде.
- Для денежных расчётов не использовать float32/float64.

  Для Go-кода дополнительно обязательны следующие правила читаемости:
- длинные функции разделять по логическим обязанностям, не вводя слои без
  необходимости;
- SQL-запросы оформлять многострочно с понятными отступами;
- не смешивать SQL, HTTP-обработку и бизнес-вычисления в одной функции;
- добавлять контекст к ошибкам через `fmt.Errorf` и `%w`;
- после итерации `Rows` проверять `rows.Err()`, а `Rows` закрывать в той же
  функции, где они получены;
- сложные вычисления выделять в небольшие тестируемые функции;
- сохранять атомарность существующих транзакций PostgreSQL.


## Архитектура и сбор данных

- Каждый источник данных реализовывать отдельным адаптером.
- Не смешивать получение данных, HTML/JSON-парсинг, нормализацию и сохранение в PostgreSQL.
- Использовать общую модель данных, независимую от конкретного сайта.
- Сохранять идентификатор источника и оригинальный идентификатор записи.
- Различать объявления, кадастровые данные и зарегистрированные сделки.
- Не смешивать цены предложения с фактическими ценами сделок.
- Все сетевые операции и операции с базой данных должны поддерживать `context.Context`.
- Все HTTP-клиенты должны использовать timeout и ограничение частоты запросов.
- Обрабатывать HTTP 429 с учётом `Retry-After`.
- Не реализовывать обход ограничений источников.
- Не считать отсутствие объявления при одном обходе подтверждением его удаления или продажи.

## Целостность и качество данных

- Импорт должен быть идемпотентным: повторная загрузка одинаковых данных не должна создавать дубликаты.
- Сохранять историю значимых изменений объявлений.
- Использовать UTC для хранения временных меток.
- Не заменять отсутствующие числовые значения нулями.
- Денежные суммы хранить в точных числовых типах с указанием валюты.
- Не использовать `float32` или `float64` для денежных расчётов.
- Для идентификации объекта недвижимости не полагаться исключительно на адрес.
- Не объединять предполагаемые дубликаты автоматически без достаточной уверенности.
- Сохранять происхождение данных (source provenance).
- Миграции базы данных должны быть версионированными.

## Тестирование

- Писать unit-тесты для парсеров, нормализации, дедупликации и расчёта изменений.
- Использовать локальные HTML/JSON-фикстуры вместо обращения к реальным сайтам в unit-тестах.
- Не выполнять интеграционные тесты на существующих или production-базах.
- Интеграционные тесты с PostgreSQL запускать только в изолированной среде.
- Не изменять существующие тесты исключительно ради получения успешного результата.
- После изменений Go-кода выполнять `gofmt`, `go vet` и релевантные тесты.
- При невозможности запуска тестов явно указывать причину.

## Управление изменениями

- Перед существенными архитектурными изменениями описывать предполагаемые изменения и их последствия.
- Не добавлять новые библиотеки, инфраструктурные компоненты или сервисы без обоснованной необходимости.
- Не проводить масштабный рефакторинг несвязанных компонентов.
- Не удалять исходные данные, фикстуры и миграции без явного разрешения.
- Не выполнять разрушительные операции с PostgreSQL без явного подтверждения.
- Не запускать массовый live-сбор без предварительной проверки разрешённости доступа.
- Не делать git commit или git push без явного разрешения.
