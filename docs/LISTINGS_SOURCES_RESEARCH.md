# Исследование источников актуальных объявлений

Дата исследования: 2026-11-08

## Вывод

Публичная доступность страницы объявления не является разрешением на её
автоматизированное извлечение. Для FincaRaíz, Metrocuadrado, Ciencuadras и
Properati не удалось подтвердить открытый read-API или разрешение на массовый
сбор публичного каталога.

Наиболее практичный первый путь — авторизованный API CRM/агрегатора Wasi для
собственного или явно подключённого агентского инвентаря. Второй кандидат —
официальный API Mercado Libre, но до реализации нужно подтвердить права
приложения на чтение и длительное хранение данных объявлений. Третий путь —
прямой XML/JSON/API-feed от агентства, которое владеет объявлениями и письменно
разрешает импорт.

Массовый live-сбор в рамках этого исследования не выполнялся. Адаптеры для
порталов не включены, так как отсутствие технического барьера не подтверждает
разрешённость доступа.

## Детали источников

### Wasi

Документация Wasi описывает поиск объектов через API, включая JSON-ответы,
`id_property`, параметры фильтрации, `skip`/`take`, сортировку и поля объекта.
Для запросов нужны реквизиты компании и токен; API не является анонимным
каталогом всего рынка. Поэтому адаптер должен импортировать только тот
инвентарь, на который у владельца проекта есть право доступа и хранения.

Полезные официальные страницы:

- [Wasi — подключение Metrocuadrado](https://ayuda.wasi.co/es/article/como-activar-la-conexion-con-el-portal-metrocuadrado)

### Mercado Libre

Официальная документация описывает API поиска и получения item. Для адаптера
нужно отдельно проверить категорию недвижимости в Colombia, ограничения
приложения, допустимое хранение изображений и карточек, а также механизм
уведомлений. До такой проверки нельзя объявлять источник готовым для
регулярного импорта.

Полезные официальные страницы:

- [Mercado Libre Developers Colombia](https://developers.mercadolibre.com.co/)
- [Items and search API](https://developers.mercadolibre.com.co/en_us/items-and-searches)
- [Notifications](https://developers.mercadolibre.com.co/en_us/notifications)

### Порталы объявлений

Для Ciencuadras критическим ограничением являются собственные условия сайта:
они запрещают автоматические средства извлечения и обход защит без
разрешения. Для FincaRaíz и Metrocuadrado найденные материалы Wasi описывают
синхронизацию объявлений клиента в портал, а не разрешение читать весь каталог
портала. Это разные режимы доступа и смешивать их нельзя.

Источники условий и интеграций:

## Рекомендованная архитектура адаптера объявлений

IGAC остаётся отдельным источником регистрационных транзакций и не должен
записывать данные объявлений в `property_transactions`. Для объявлений следует
использовать существующую общую модель `model.Listing` и отдельный адаптер
источника.

Рекомендуемый поток:

```text
ListingSource
  -> HTTP/API client
  -> page/cursor response
  -> source parser
  -> normalizer
  -> provenance + validation
  -> listings upsert
  -> listing_snapshots on meaningful change
```

Минимальный контракт может выглядеть так:

```go
type ListingSource interface {
    Name() string
    CollectPage(ctx context.Context, options PageOptions) (ListingPage, error)
}

type ListingPage struct {
    Listings   []model.Listing
    NextCursor string
    HasMore    bool
}
```

Адаптер обязан:

1. Хранить имя источника и оригинальный ID (`id_property`, `ITEM_ID` или ID
   агентства) в `source`/`external_id`.
2. Канонизировать URL только после сохранения исходного происхождения.
3. Передавать фильтры и пагинацию API на сервер, а не скачивать весь каталог.
4. Использовать timeout, `context.Context`, последовательный rate limit,
   ограниченные повторы и обработку `429`/`Retry-After`.
5. Не включать телефоны, email и имена частных владельцев.
6. Обновлять cursor только после успешного upsert соответствующей страницы.
7. Создавать snapshot только при изменении значимых полей, включая цену.
8. Отдельно хранить объявление и историю объявления; не смешивать их с IGAC.

Для Wasi первым будет нужен `WasiSource`, который получает credentials только
из переменных окружения и ограничивает запросы инвентарём разрешённой компании.
Для Mercado Libre потребуется отдельный token-aware клиент и проверка условий
приложения. Эти реализации не добавлены в текущем исследовательском изменении:
нет выданных credentials/договора, а запуск без них не дал бы проверяемый
результат.

## Что нужно получить перед реализацией

- подтверждение владельца данных или партнёрского портала на автоматизированное
  получение;
- точный scope: собственные объявления, объявления партнёров или весь каталог;
- разрешение на хранение полей и изображений и срок хранения;
- стабильный ID, поле времени изменения и правила удаления/деактивации;
- лимиты API, rate limit, pagination/cursor и формат ошибок;
- тестовые credentials или локальная JSON-фикстура, не содержащая секретов.

До получения этих сведений первый live-адаптер не следует объявлять готовым и
не следует выполнять массовую загрузку. IGAC-просмотр и импорт транзакций
остаются независимыми от этого решения.
